Bank Reconciliation Exceptions Agent

Every month, accountants compare the bank's records with their company's own. Plain rules match most lines. An AI agent investigates the ones that don't match, suggests a fix, and waits for a person to approve it.

Where the work goes

How it works

  1. Match the obvious ones. Same invoice number, same amount, dates a few days apart. Each line can only be matched once, so a payment entered twice can't hide inside a match.
  2. Investigate the rest. The agent looks up the bank and ledger rows and searches the paperwork: invoices, wire confirmations, the bank's fee schedule. It can only read, never change anything.
  3. Suggest, don't post. It writes a fix and saves it as pending. There is no tool it could use to change the company's books.
  4. A person decides. The reviewer sees the case, the suggested fix, the evidence and all the agent's reasoning before approving or rejecting.
  5. Score every run. The data is made with an answer key the agent never sees. Each run is scored on both the type of problem and whether the fix moves the money by the right amount.

    How the scoring works

    1. When the data is made, each hidden problem is written down in an answer key. That file is kept out of the database the agent can search, and a test checks it stays out.
    2. The answer key and the agent's work use completely different ID numbers, so nothing can link them by accident. The scoring script matches them up using the bank and ledger rows they have in common.
    3. Naming the right problem but suggesting the wrong amount still counts as wrong. To pass, a case needs both.
    4. Which expense account to use is a matter of opinion, so I report whether it matched but don't count it against the agent.

    How to read these numbers

    • It's a small test. 16 cases, two or three of each type. One wrong answer would drop a type from 100% to 50%, so these numbers show where to look rather than how often it's right.
    • It's one run. AI output changes a bit each time. I'd need to run it several times to say anything about consistency.
    • The data is made up and tidy. Every problem has clear evidence somewhere. Real bank statements have partial payments, one deposit covering several invoices, and missing paperwork. None of that is here.
    • The rules did the easy work first. Plain matching handled 114 of 125 bank lines, so the agent only saw the genuinely tricky ones.
